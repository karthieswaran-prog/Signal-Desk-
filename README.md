# SignalDesk — Revenue Intelligence Inbox

## What this prototype does
- Dashboard metrics calculated from records loaded in the browser.
- Conversation inbox with search, source-type/route/review filters and transcript evidence.
- Rule-assisted multi-route suggestions with saved manual route overrides.
- Import of the assessment JSON envelope, revision-aware upsert, duplicate replay protection and local persistence.
- ZIP export with `manifest.json`, a manager brief, and one Markdown output per active route assignment.

## Run in VS Code
1. Extract this project ZIP to a folder.
2. Open the folder in VS Code.
3. Put the provided assessment files in `data/01_initial.json` and `data/02_update.json`.
4. Install the VS Code extension **Live Server** (or use any local static server).
5. Right-click `index.html` → **Open with Live Server**.
6. Open **Imports & updates** and import the initial JSON file using the file picker. Repeat the import to test idempotency.
7. Open M07, save a manual route, import `02_update.json`, then import `01_initial.json` again. Refresh the browser and verify the manual route and newer revision persist.
8. In **Exports**, choose **Build & download export ZIP**.

You can also use the two quick-import buttons when serving the project from a local web server and placing the JSON files under `data/`.

## Data format and identity
The importer expects an envelope with `batch_id`, `revision`, and `records`. It uses `(source_type, source_id)` as the logical key. Same/older revisions are ignored. A newer revision replaces the source record while preserving any explicit manual route. When the source text changes, the record is marked for review rather than silently presenting old analysis as current.

## Metrics
- **Unique source records:** distinct source-type/source-ID pairs currently loaded.
- **Usable supplied text:** nonblank call transcript or at least one nonblank meeting turn.
- **Coverage:** usable-text records divided by selected records; the source-type filter changes the denominator.
- **Needs human review:** missing text, ambiguous routing, or analysis marked stale.
- **Route assignments:** can exceed unique records because a record can have multiple routes.
- **Person grouping:** calls use the source rep field; meetings use organiser email. Organiser is not assumed to be salesperson or attendee.

## Routing and analysis limitations
Routing is deterministic, rules-assisted classification intended as a review aid. It is not a paid/live AI model and should not be described as one. The app does not infer pipeline value, win probability, account joins, staff roles, or deal outcomes. Missing text is not proof that no conversation occurred. The app is a browser-local prototype; localStorage is device/browser-specific, not a shared database.

## Export contents
`signaldesk_export.zip` includes `manifest.json`, `manager_brief.md`, `README.txt`, and `outputs/<route>/<record>.md`. Manifest output paths are relative to the ZIP and each active output path is generated by the exporter.

## Findings to validate against the actual loaded dataset
Use the supplied source files to confirm the examples below before submitting:
1. **Partner workflow needs scalable referral intake.** Evidence: M01, turn 20 says the process cannot depend on manually writing every email; turn 21 proposes a unique link. Product impact: partner/vendor routing and manager follow-up output.
2. **Electronic-invoicing scope and forecasts contain uncertainty.** Evidence: M02, turn 18 distinguishes current received-invoice volumes from estimated issued volumes. Product impact: preserve uncertainty and require validation rather than present estimates as equally certain.
3. **Contact preferences must be respected.** Evidence: C09 contains the exact statement “No, please don't use my name.” Product impact: route to sales coaching/human review; do not recommend contacting a named referral using that person's name.
These are candidate findings grounded in the assignment's embedded adapted conversation examples; check the exact source IDs/turns in the JSON delivery before final submission.

## Rejected decision
Rejected: automatically mark every meeting organiser as the account executive/owner and rank people by activity. The dataset does not establish job roles, attendance, a full team-day sample, or complete account history. Trade-off: the prototype shows source-reported rep/organiser fields and selected-record counts instead of potentially misleading performance rankings.
